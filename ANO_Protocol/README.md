# 有线串口连接匿名科创上位机

## 文件与接口

| 文件 | 用途 | 初始化入口 |
| --- | --- | --- |
| `Hardware/usart1.c`、`usart1.h` | 恢复的蓝牙串口初始化，配合原有 `buletooth.c` | `USART1_Init()` |
| `Hardware/USART.c`、`USART.h` | 新的有线串口驱动，含接收中断、错误清除和二进制发送 | `Serial_Init()` |
| `ANO_Protocol/ANO_Protocol.c`、`.h` | 匿名 V7 协议、SC/AC 校验、姿态上传、参数读写和校准命令 | `ANO_Protocol_Init()` |

两个驱动是独立、择一使用的版本：蓝牙由 `usart1.c/.h` 配合 `buletooth.c` 实现，有线串口由 `USART.c/.h` 实现，匿名协议只调用有线串口接口。

当前 Keil 工程只编译有线串口版本。`usart1.c`、`buletooth.c` 仍可在工程列表中看到，但已取消 **Include in Target Build**，`app_cfg.h` 中 `BLUETOOTH_EN=0`。因此可以将这两个蓝牙源文件移出工程，有线串口和姿态任务不依赖它们。

`BSP_Init()` 已按顺序调用协议初始化和 `Serial_Init()`。`TaskGY86` 在任务中处理协议、上传姿态，中断只收字节和报告接收错误。

PB6/PB7 的硬件复用功能是 **USART1**，所以有线 `USART.c` 里的寄存器名称仍为 `USART1`；蓝牙备份保留原有 PB6/PB7 设置。这里按两个文件版本择一编译使用，未配置两路同时工作的串口。当前接 USB 转串口。

## 接线与上位机设置

使用 3.3 V TTL 电平的 USB 转串口模块：

| F401RET6 | USB 转串口 |
| --- | --- |
| PB6（TX） | RXD |
| PB7（RX） | TXD |
| GND | GND |

在匿名科创上位机选择相应 COM 口，波特率与固件保持一致，设置 **8 数据位、无校验、1 停止位、无流控**。协议使用所提供文档的 V7 格式；设备目标地址为 `0x05`，也接收 `0xFF` 广播。参数响应发往上位机地址 `0xAF`。

注意：正常模式实际波特率以 `Hardware/USART.h` 的 `SERIAL_BAUDRATE` 为准，当前为 **115200**，电脑端必须设置相同值。下述可选自检模式也固定为 **115200**。

当前已关闭串口自检，恢复姿态解算和匿名协议收发。本次排查中外置模块识别为 **USB-SERIAL CH340（COM8）**，上位机选择该模块对应的端口；**COM7 为板载 ST-Link 虚拟串口**，默认不连接 PB6/PB7。重新插拔设备后 COM 号可能变化，以设备管理器为准。

上电后先静置，等待陀螺仪收集 400 个稳定样本，再观察姿态窗口。姿态任务约每 5 ms 运行一次，每 10 次上传一组数据；实际频率还受采样和串口发送耗时影响。

上传数据包括 `0x01` 加速度/角速度、`0x02` 磁力计、`0x03` 欧拉角和 `0x04` 四元数。欧拉角按度数乘 100 编码，四元数按分量乘 10000 编码。尚未接入气压计，气压计状态为 0。`0x03/0x04` 的最后一个字节为本项目状态位：bit0 姿态就绪、bit1 陀螺仪已校准、bit2 磁力计初始化成功、bit3 正在融合磁场、bit4 正在磁标定、bit5 磁标定成功。

## 校验和收发排查

### 无需增加接线的串口自检

`Hardware/USART.h` 的 `SERIAL_SELF_TEST_EN` 当前为 **0**，使用正常姿态和匿名协议模式。需要再次自检时将其改为 **1**：原任务改为串口自检，不初始化/读取 GY86、不解算姿态，也不处理或发送匿名协议报文。PB6/PB7 和原有 USB 转串口接线保持不变，蓝牙备份仍不参与工程编译。

1. 自行在 Keil 编译、下载，点击 Run。关闭匿名上位机的串口，避免占用同一个 COM。
2. 串口助手选择 USB 转串口模块的 COM，设置 **115200、8N1、无流控**；选择文本接收/发送，关闭本地回显、自动发送和 HEX 发送。
3. 正常时约每秒收到一行 `UART TEST PB6-TX PB7-RX 115200 8N1`。这验证板子到电脑的发送方向。
4. 手动发送 `ABC123`，板子应原样回传 `ABC123`。不要只看助手的“发送记录”，要检查接收区；若不附加换行，新增接收字节应为 6。
5. Watch 观察 `Serial_Test_Debug`，此模式下不再看 `ANO_Protocol_Debug` 的计数。

| 自检字段 | 含义 |
| --- | --- |
| `heartbeat_count` | 心跳发送成功次数；表示交给串口，不代表电脑已经收到 |
| `irq_count` | USART1 中断进入次数 |
| `rx_bytes`、`last_rx_byte` | 中断读到的字节数及最后一字节；包括伴随硬件错误的字节 |
| `echo_bytes` | 无错误接收字节经队列交给串口回传的总数 |
| `rx_errors`、`last_error_flags` | 硬件接收错误次数及最近一次 SR 错误位 |
| `rx_overflows`、`tx_errors` | 自检接收队列溢出、发送失败次数 |

只看到心跳而发送后没有回传：检查电脑 TXD 到 PB7 的方向、电脑发送设置，并观察 `rx_bytes/rx_errors/irq_count`。心跳和回传都正常，说明本次测试的串口双向链路可用，再恢复协议模式排查。心跳乱码，先核对 115200 和 8N1；心跳完全不可见且 `heartbeat_count` 增加，检查 COM 选择、PB6 到模块 RXD 以及共地。

自检结束，将 `SERIAL_SELF_TEST_EN` 改为 **0** 后重新编译、下载，即恢复原来的姿态任务和匿名协议；正常模式使用 `SERIAL_BAUDRATE`（目前 115200），电脑端也应设置相同波特率。无需新增源文件或修改 Keil 工程列表。

### 匿名协议模式

帧格式为 `AA D_ADDR ID LEN DATA SC AC`。SC 和 AC 都从 `AA` 开始，计算到最后一个 DATA 字节，均只保留低 8 位：

```text
SC = 0; AC = 0
逐字节：SC += byte; AC += SC
```

SC/AC 本身不参与上述计算。接收时两项必须都正确，才会处理参数或校准命令。命令及参数写入的 `0x00` 应答携带原帧的 `ID、SC、AC`；应答自身也有独立的 SC/AC。

在 Keil Watch 添加 `ANO_Protocol_Debug`：

- `tx_frames`：每上传一组数据增加 4，表示数据已交给串口。
- `rx_frames`：收到发给本机且校验正确的帧时增加；上位机只看姿态、不发命令时可以保持 0。
- `rx_bytes`：串口中断交给协议的原始字节数，在地址和校验判断前计数。点击读取参数后仍为 0，说明没有无硬件错误的接收字节进入协议；先检查 COM 口、TXD 到 PB7 的线路、串口接收/中断配置。
- `address_errors`：以 `AA` 开始但目标地址不是 `05/FF` 的候选帧头计数；如果增加，核对上位机目标设备地址。
- `last_address`：最近候选帧头的目标地址；`last_id`、`last_length` 为通过地址筛选后最近读到的功能码和长度，各字段可能来自未完成的候选帧，不能单独当作完整帧。
- `rx_capture_count`、`rx_capture[0～31]`：启动后最先收到的最多 32 个原始字节，按接收顺序保存，填满后冻结。用于检查上位机实际发送的地址、功能码和帧头；调试时以十六进制查看。需要重新捕获时复位主控，不要在运行中调用协议初始化或只改计数。
- `checksum_errors`、`length_errors`：错误校验或超长帧的计数。
- `uart_errors`、`rx_overflows`：串口硬件接收错误、接收队列溢出计数。
- `tx_errors`：串口未开启或发送超时计数。

正常通信时错误计数应保持 0。驱动遇到接收错误或溢出会丢弃中断前后的残帧，等待下一帧。半帧超过 100 ms 未完成也会复位接收状态。不要往此端口混入 `BLE_SendString()`、`printf()` 等文本。

`tx_frames` 增长只说明主控已将报文写入串口，不能证明电脑已收到。若它增长但上位机完全没有数据，可先关闭上位机串口，用串口助手打开同一 COM 口，以 `SERIAL_BAUDRATE` 对应的波特率、8N1、HEX 接收，检查是否出现 `AA FF 01 0D ...`、`AA FF 02 0E ...`、`AA FF 03 07 ...`、`AA FF 04 09 ...`。两款软件不要同时占用同一 COM 口。

可用于串口助手十六进制发送的例子：

```text
读取参数 11：       AA 05 E1 02 0B 00 9D B5
将参数 11 写为 100：AA 05 E2 06 0B 00 64 00 00 00 06 DD
```

## 校准及 PID 参数

上位机的陀螺仪校准命令会重新开始静止零偏采样；采样期间保持模块不动。磁力计校准命令会开始约 30 秒的采集，在此期间缓慢绕三个轴转动、覆盖各个朝向，到时自动结束。同一轮的重复磁校准命令只应答，避免上位机重发导致提前结束。校准结果可从姿态状态位观察；应答仅表示命令帧已收到。

参数 `11～19` 依次对应 `ANO_PID_Groups[0～2]` 的 P/I/D，原始整数范围为 `0～65535`，上位机显示的缩放需与使用这些参数的控制器约定一致。目前只支持 RAM 中的读写，断电不保存，也尚未接入电机 PID 闭环。

## 恢复使用蓝牙

切换回蓝牙版本时：

1. 将 `USART.c` 和 `ANO_Protocol.c` 移出工程或取消 **Include in Target Build**，重新勾选 `Hardware/usart1.c`、`Hardware/buletooth.c`。
2. 在 `app_cfg.h` 中设置 `USART_EN=0`、`BLUETOOTH_EN=1`。
3. 在 `BSP.c` 中将有线头文件改为 `bluetooth.h`，删除匿名协议头文件及 `ANO_Protocol_Init()` 调用，将 `Serial_Init()` 改为 `USART1_Init()`。
4. 在 `app.c` 中删除匿名协议头文件及 `ANO_Protocol_Process()`、`ANO_Protocol_SendTelemetry()` 调用，恢复注释中的 `BLE_SendAttitudeData()`。

重新编译、下载后即使用独立的蓝牙版本；当前有线版本无需以上切换。

蓝牙头文件是 **`Hardware/usart1.h`**，已由同目录的 `bluetooth.h` 引入。工程中未使用的 `System/usart1.c/.h` 是 PA9/PA10 版本，不要加入当前工程，也不要误用它的带波特率参数的初始化声明。
